# codex-method — PRD

## One sentence

Enable a human to direct parallel development through one Codex main session and its native
workers, reviewers, and helpers, using evidence-bearing GitHub collaboration where applicable and self-contained ordinary task contracts.

## Why build it

DevStandard provides the method being adapted: human time otherwise goes to scheduling; completion
claims can lack evidence; irreversible actions need explicit authority; repeated peripheral review
can lose the goal; fresh sessions lose conventions; and rules accrete beyond their value. This
adaptation retains those problems and the reuse of GitHub flow, worktrees, CI, protection, and
upstream superpowers craft while selecting Codex as the only host. Source history remains source
history; this repository's decision log starts at 0000.

## Features as user value

- Discuss a wanted result, reason, Bounds, and observable Done-check once; an explicit instruction
  supplies authorization within its scope. The orchestrator carries settled work unattended to a PR
  and interrupts only for direction, irreversible authorization, or a blockage with no sound route.
- Keep one responsive conversation while workers own separate task lanes. An issue's ordered record
  survives handoffs; native completion remains a claim until evidence and review establish delivery.
- Inspect final-state evidence, PREWRITE/DELIVERY accounting, actual model attribution, and an issue-
  linked PR driven to green. Workers trace root causes wherever needed while writing only in Bounds.
- Obtain fresh independent Goal/Floor review. Only goal fulfillment and evidence/authorization
  Floors decide readiness; Notes do not trigger review rounds. Repeated nonconvergence earns a
  decision about the work rather than endless polishing.
- Integrate only through an exact-head/base local acceptance receipt and green CI for the merge
  result, then clean up owned artifacts and perform a separately authorized release.
- Keep general collaboration agreements in one method source, delivered whole to main and child
  roles without role promotion or a permanent user-level AGENTS bootstrap. Ordinary research and
  document tasks keep their caller's contract; they need no invented lane or PR.
- Maintain product, architecture, ADR, and consequential design records at their own triggers;
  recover native bindings explicitly rather than inventing handoff documents or authority.

### Non-goals and boundaries

No second host, external agent executor, quota balancing, silent model substitution, invented
coordination hierarchy, blanket setup ceremony, or perfection requirement. The method supplements
the native harness and governs GitHub collaboration; task-local helpers remain the caller's
responsibility. Deterministic bulk operations use scripts. Model endpoints for bulk extraction
are a needing project's declared tool, not a substitute worker or reviewer.

The declared threat model covers ordinary shipped command and tool paths. It does not promise
malicious same-credential containment, per-child OS sandbox isolation, arbitrary MCP-write
containment, or protection on a compromised host. Refusals never authorize bypasses; secrets are
never copied to make a task work. Source fallback and acceptance-reuse designs remain routed and
explicitly unqualified until their mechanical properties are implemented and demonstrated.

## Definition of done

1. Fresh target startup delivers the whole operative orchestrator context before task actions;
   workers receive the complete worker role, native mechanics, and current packet; reviewers receive
   a current pinned contract without session history. Capture actual host request/delivery evidence.
2. Explicit model/effort and real role identity reach native V2 children; actual allowed operations,
   role denials, completion, and retained-handle continuation are demonstrated on the named version.
3. A constructed review lifecycle rejects forged remote metadata, missing receipts, head/base races,
   malformed verdict readiness, pending re-entry, and Notes-only re-review; raw publication and round
   accounting preserve the accepted contract. No historical status capture is fabricated.
4. A constructed guard accepts only the current default branch/base, exact accepted receipt/head,
   and GitHub Actions merged-result check with no failed head checks; stale identities refuse.
5. Installation into an explicit target preserves unrelated settings, refuses collisions, discovers
   the method roles, and keeps package hooks separate from role config. Dependency skills resolve.
6. Source rules, references, research, and historical decisions have a durable routing or explicit
   departure. Repository links, routing checks, required local checks, and package consistency pass.
7. A live authenticated worker-to-PR-to-review-to-guard sequence is captured before claiming runtime
   readiness. Fixture successes, metadata presence, and source-project tests are separate evidence.

The desired outcomes are less human scheduling, evidence-backed completion, controlled irreversible
acts, retained goal substance, durable conventions, and a readable rules layer. No supported lane
count or production outcome is asserted by the document itself. Every rule and mechanism must
serve those problems or the reused collaboration/craft structures; unexplained machinery is removed
through an explicit source disposition, never a silent loss.

## Constraints

Codex 0.160.0 and 0.160.1 native V2 are the qualified hosts within the captured Linux and
Windows evidence limits in the architecture and native harness. Every worker, reviewer, helper
and arbitration uses explicit `gpt-6.1-sol`/`high` unless a direct, specific human instruction
overrides its named dispatch; no automatic model ladder exists. Main-session settings remain
the human's choice. Exact role bindings are in the orchestrator page. Account
availability and live operation require separate evidence. Missing tools, models, skills, or gate
properties are disclosed and block dependent work; no quota-driven substitution is allowed.
